## Contract adaptations and next-owner boundaries

- The frozen contract has **no GET single application** route. `/applications/:id?job=<job-id>` reloads the authorized job and walks its paginated application list to find the record. Links always preserve that job context. An incomplete direct URL gives a clear instruction to open it from the job.
- There is **no resume-list endpoint**. Candidate detail shows uploads made in that screen session; existing linked versions remain reachable through application detail. No invented route, public file URL or browser storage index was added. Reusing an older unlinked upload across reload would require a future contract/backend read endpoint.
- There is **no GET assignments endpoint**. Assignment controls explicitly replace the full list and do not pretend that initially unchecked options describe existing grants.
- T8.2's users implementation currently ignores optional search/role filters. Admin performs these filters over authorized paginated user reads; the regression test includes a matching reviewer on the second server page. Other list screens use their implemented server search/pagination.
- Dashboard is the explicitly permitted meaningful shell, with no fabricated counts. Aggregates/audit remain T8.8. Application screening/results/review remain T8.9; no nonworking generate/start button or legacy synchronous AI path is exposed. Results remains available unchanged for stored-result integration.
- No remaining T8.7 blocker. T8.9 can use the exported HTTP/mock PlatformClient, workspace context and application routes; API client/shared App ownership must transfer serially after this task settles.
