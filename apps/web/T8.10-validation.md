# T8.10 validation — UI quality and accessibility pass

Branch `hunglv2/m7-ui-polish` (base `a034cff`), 2026-11-23, Node v26.12.0, pnpm 9.15.4. No commit was made. No API contract, scoring, queue, seed, manifest or lockfile file was changed. The diff covers web presentation, layout and styles in `apps/web/src/`, one new component test file, an update to two assertions in `App.test.tsx`, and the screenshots in `docs/screenshots/t8/`.

## What changed

### Shared system (`app/ui.tsx`, `app/names.ts`, `app/context.tsx`, `styles.css`)

- **Vietnamese formatting.**
  - Dates use one `Intl` formatter (`07:54 23/11/2026`, with no seconds). Lists use date only (`23/11/2026`).
  - Numbers use `vi-VN` (`42,9`, `1.250`, `36,5–51,5`, `0,1 giây`).
  - The coverage threshold is rounded, so a float such as `80.00000001%` can never be shown.
- **Status badges always show an icon as well as a colour.** Each status has its own shape:

  | Shape         | Statuses                       |
  | ------------- | ------------------------------ |
  | clock         | queued, pending approval, hold |
  | spinner       | running                        |
  | refresh       | retry_wait                     |
  | check         | completed, approved, open      |
  | ✕             | failed, reject                 |
  | dashed circle | draft                          |
  | lock          | closed                         |
  | sparkle       | new                            |
  | star          | shortlist                      |

  Criterion level badges get icons too: check, partial, ✕, ?, eye. Withheld scores use a dashed ring and "—". The coverage meter is a `role="meter"` and has a visible threshold tick.

- **States.**
  - Loading is a `role="status"` row.
  - An error is a `role="alert"` block with an icon and a **Thử lại** button.
  - When you retry after an error, a spinner now shows. Before this change, `useLoad` refreshed silently and there was no feedback.
  - Empty states have an icon, guidance text and an optional action. Search, no-data and reviewer cases each have their own copy.
  - Forms set `aria-busy` while submitting, and the success notice has an icon.
  - Pagination is hidden when there is only one page. Before, every list ended in a redundant "1 kết quả · Trang 1/1" bar. When pagination does show, it is a labelled `nav`.
- **Readable names in place of IDs.** `useCandidateNames` and `useJobTitles` resolve names through the existing `GET /candidates/:id` and `GET /jobs/:id` reads. They are used on the dashboard, job applications, the application heading and summary.
  - Reviewers cannot read candidates, so they still see `Hồ sơ #xxxxxxxx`. This is a contract limitation, not something the UI hides.
- **CSS.** A single T8.10 layer is appended to `styles.css`.
  - **Type and spacing.** The base size goes from 13 to 14 px, and no text is below 11 px. Before, captions and badges were 8–10 px. Card, row and section rhythm is consistent.
  - **Colour tokens.** Amber and rose tokens are shared by light and dark.
  - **Focus.** A focus ring (`:focus-visible`) on every control. Headings that receive focus programmatically show a ring.
  - **Rows.** One row pattern (`.p-row`) for every list. Long titles are balanced or clamped, and notes wrap.
  - **Disclosures.** Disclosure cards have a chevron.
  - **Motion.** Spinners and the pulse stop under `prefers-reduced-motion`.
  - **Print.** Print output hides the shell and aside.

## Accessibility checks

- **Keyboard-only journey.** This was run in the Orca browser at 1440×900 against the real stack, with real Tab, Enter and Arrow keys (no mouse):
  1. Tab order is: skip link, logo, navigation, sign-out, theme toggle, then main content. Signing out with Enter works.
  2. On login, Tab reaches email, then password. Enter signs in, and focus lands on `<main>`.
  3. Tab to "Khám phá vị trí tuyển dụng" and press Enter. Tab to the HR job and press Enter. Tab to **Gửi phê duyệt** and press Enter: focus goes to "Phiên bản 1" and the status "Đã gửi…" is announced.
  4. Tab to **Phê duyệt JD** and press Enter: focus goes to the version, with "Đã phê duyệt phiên bản 1…".
  5. Tab to the Lan Chi application and press Enter. Tab to **Bắt đầu sàng lọc** and press Enter: the run goes queued, then completed.
  6. Tab to the decision radio. Arrow-down selects "Đưa vào danh sách ngắn". Tab to the note, type it, Tab to **Lưu quyết định của tôi** and press Enter. The result "Đã lưu thành công." is announced, and focus returns to the panel heading.
  7. Two places lost focus to `<body>` before this pass: after login and after a JD action. Both are fixed.
- **Mobile drawer.** The existing focus trap and Escape handling are retained, and focus moves to the close button (screenshot checked).
- **Contrast (WCAG AA, computed from tokens).**
