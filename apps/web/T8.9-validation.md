### Web (`apps/web/src`)

- **`features/screenings/ScreeningPanel.tsx`.** Screening start against an approved JD version, with idempotency keys.
  - Run history is persisted, paginated, and selected through `?run=` (it survives refresh and navigation).
  - Polling runs every 2 s while any run is pending, backs off to 5 s after 60 s, and stops once all runs are terminal.
  - A calm long-wait message shows elapsed seconds, attempts and the next retry time.
  - Failures get Vietnamese explanations; the raw code and detail are kept small.
  - An explicit retry creates a new run. For `config_changed`, a retry is withheld, because it would reuse the frozen config; the panel offers "Phân tích mới với cấu hình hiện tại" instead.
  - Provenance is labeled live or "DEMO XÁC ĐỊNH". The exact PDF of the run downloads through the authorized endpoint.
- **`components/Results.tsx`.** Adds `SourceEvidence` and `sourceRange`.
  - The quote is highlighted inside the normalized source, using verified Unicode code-point offsets (`Array.from`, not UTF-16), and rendered as escaped text.
  - Page labels (with OCR marker) come only from the retained page map. When an offset is invalid or out of range, the UI says "Không có vị trí nguồn đã xác minh" and draws no page link.
  - Insufficient coverage shows "—" and "Chưa công bố điểm", never 0.
- **`features/reviews/ReviewPanel.tsx`.** A decision form with three accessible radio cards (hold, shortlist, reject) and a required trimmed note.
  - It sends `expected_application_revision`. On a 409 the note is kept and "Tải lại hồ sơ, giữ ghi chú của tôi" appears.
  - The current-decision summary and history are attributed to a named person: admins see names from `/users`; others see "(bạn)" or a stable short user reference, because the contract carries no reviewer names.
  - Banners flag an old run and a decision based on an earlier run.
- **`features/audit/Audit.tsx`** (admin route `/audit`, plus a sidebar entry): filters by activity (Vietnamese select of every action the API writes), job, and date range; paginated; names actors.
- **`app/Dashboard.tsx`:** real counts, rows awaiting a decision, rows needing a retry, and recent applications.
- **`app/context.tsx`:** `useLoad().reload()` now refreshes in place instead of unmounting. The smoke found that saving a decision remounted the whole application view and dropped the "Đã lưu thành công" confirmation.
- **Smaller fixes:**
  - status badges for run states (failed and reject are terracotta; queued, running and retry are amber)
  - gentler reject label "Chưa phù hợp"
  - Vietnamese messages for `login_throttled`, `invalid_origin`, `ai_unavailable`, `screening_in_progress` and `config_changed`

### Seed and operations

- **`apps/api/src/db/seeds/demo.ts`** (plus `demo-jds.ts` and `demo-envelope.ts`) follows plan §2.9.
  - Two jobs built from the reviewed `jd-py-real` and `jd-hr-real` templates: one approved JD (7 criteria) and one draft JD.
  - Six synthetic candidates and PDFs.
  - Archived runs covering scored, scored-needing-manual-review, insufficient coverage and failed, plus one named shortlist decision and audit rows.
  - Totals come from a port of `app/scoring/engine.py`; the rubric matches production (0.7/0.4). Seeded runs are labeled deterministic, synthetic and archived fixtures.
  - The seed is idempotent under an advisory lock, never overwrites passwords, user work or storage objects, and writes files with `wx` mode `0600`.
- **`scripts/demo/{reset,backup,restore,common}.mjs`:**
  - Reset refuses anything other than local `:55432/rms_ai_demo`, a matching migration URL, a local Docker socket, this checkout's canonical non-symlink storage, and an explicit `--confirm rms_ai_demo`.
  - Backup always includes the database and private PDFs with SHA-256 manifests.
  - Restore requires an empty database and empty storage and verifies every checksum.

**Defects found and fixed during the smoke:**

1. Saving a decision unmounted the page (`useLoad` reload).
2. The radio inputs in the decision cards were mispositioned by the generic form-input rule.
3. Retrying a seeded deterministic fixture can never succeed under live config (`config_changed`), which is correct immutability. The UI now explains this and offers a new run.
4. The audit action filter needed exact codes, so it became a labeled select.
5. Failed badges were green.

**Observations, not defects (owned elsewhere):**

- `/health/ready` reports `worker.status: "unknown"` while the worker processes jobs normally.
- The in-memory login throttle (10/IP/15 min) is hit by rehearsal scripts, so restart the API.
- Starting a screening on unchanged inputs returns the existing run (idempotent by design).
