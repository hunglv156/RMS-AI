## Behavior and plan interpretations

- Every registered internal route requires `Authorization: Bearer <AI_INTERNAL_TOKEN>`; `/health` remains public. Lifespan startup rejects a missing/blank token outside explicit `AI_TEST_MODE=true`; test mode never bypasses route authentication.
- The authenticated `/internal/v1/screening-manifest` follows the frozen T8.1 fields. Its SHA-256 fingerprint covers recursively sorted compact UTF-8 JSON excluding `fingerprint`, with integral numbers canonicalized for Node consumers. It declares `AI_BUILD_REVISION` when supplied, otherwise a reproducible digest of all application Python sources. The build digest pins fixed algorithm/default settings, alongside explicit provider/model, prompt digest, rubric, retrieval, parser/normalization, hedge/escalation, retry and deadline fields. URL user information, query strings and fragments are excluded; credentials and service tokens are never returned.
- Screening preserves multipart PDF plus JSON-string JD and the existing scoring pipeline. It requires the T8.1 headers `X-Expected-Config-Fingerprint`, `X-Request-ID`, and `X-Run-ID`; missing headers return 422, drift returns 409 `config_changed` before provider/embedder/extractor resolution. Successful responses add the actual manifest/fingerprint and exact assessed source with retained page ranges, tool versions and Unicode code-point offsets.
- `source.normalized_text_sha256` and existing `screening.versions.cv_sha256` both hash the exact UTF-8 normalized text, **not PDF bytes**. T8.6 must separately preserve/verify the uploaded file's binary hash from its frozen resume record. Tests cover emoji/Vietnamese, verified quote slicing/page association, separate binary/text identities, and real subprocess extraction.
- Deadlines use T8.1's shared `AI_REQUEST_TIMEOUT_MS=150000` and `EXTRACTION_TIMEOUT_MS=45000`, validated as positive/finite, capped at those maxima, with extraction strictly shorter than aggregate. The route's aggregate timer includes request processing and shares one budget across primary, hedged, escalation and provider retry work; responses use safe `request_timeout` or `extraction_timeout` codes. Distinct `llm_schema_error` and `llm_rate_limited` codes let the worker distinguish nonretryable structured-output failure from transient throttling.
- Extraction runs in a private-pipe subprocess with its own POSIX process group, killed/reaped on timeout or cancellation. HTTP disconnect cancels screening/extraction. Short injected deadlines test a real slow parser/OCR child process tree, caller cancellation, HTTP disconnect, primary/escalation sharing, and the real provider's retry/hedge cleanup without waiting 150 seconds. Existing pipeline/scoring regressions still pass.
- `AI_PROVIDER_MODE=deterministic` explicitly selects an injectable offline provider through the same extraction, retrieval, validation and scoring endpoint. Manifest mode/provider/model and assessment reasons visibly identify the demo; it conservatively returns `unknown` with missing information for every criterion, exercising insufficient coverage rather than inventing qualifications. Normal mode is `live` and never substitutes deterministic results after failure; existing primary-preserving escalation behavior remains intact.

No T8.3 blocker remains. Worker persistence, authorization of result reads, browser highlighting, richer seeded demo scenarios, and live-provider E2E remain with their planned owners.
