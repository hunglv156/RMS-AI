# Platform foundation (T8.1)

This package reserves feature modules for T8.2–T8.9. Only `/health/live` and `/health/ready` are implemented. Public feature controllers will use relative paths beneath the bootstrap's `/api/v1` prefix. Health remains unprefixed; readiness requires PostgreSQL, while reporting Redis/AI as degraded and worker heartbeat as unknown until T8.6 implements it.

NestJS 11.1.11 uses the Express adapter. All new dependencies are pinned and installed with Node 26.12.0 / pnpm 9.15.4; existing web/AI dependency versions are retained. Nest's [v11 requirements](https://docs.nestjs.com/v11/first-steps) allow Node >=20. `CommonModule` globally exports one `Database` provider to all registered modules and the worker. Feature owners can register providers/controllers/exports inside their modules without editing `AppModule` or `WorkerModule`.

The common directory defines sanitized error responses, request IDs, environment/deadline validation and authorization/audit/storage interfaces with DI tokens. Authorization and audit implementations belong to T8.2; filesystem storage belongs to T8.5; queue consumers, heartbeat and reconciliation belong to T8.6. `db/repository.ts` provides typed row and transaction read/lock seams. Historical records remain protected by the migration even when direct SQL bypasses future handlers.

Use a root `.env` with the placeholders in `.env.example`, following `infra/migrations/README.md` for restricted runtime credentials. Environment variables override files. API and worker must share one absolute `FILE_STORAGE_ROOT`; relative paths resolve from their working directory (pnpm uses `apps/api`). Never serve that directory statically. Start local dependencies with `docker compose up -d postgres redis`, migrate, then run `pnpm api:dev` and `pnpm worker:dev`. Compiled entrypoints are `pnpm --filter @rms-ai/api start` and `worker:start` after build. No AI/provider call is made during bootstrap.

`test:unit -- <suite>` and `test:integration -- <suite>` discover `test/<suite>/**/*.unit.test.ts` and `*.integration.test.ts` using Node's test runner with tsx. Integration runs force a separate local test DB, `rms_ai_test` Redis prefix and a temporary private storage directory, removed on completion. A requested nonexistent suite fails rather than silently passing. The schema suite creates the test DB with its owner credentials and verifies guards using the restricted group. Future suites should use the same environment and roll back or clean only their own records; they must never clear the development DB or global Redis.

`test/fixtures.ts` provides synthetic factories plus a stable baseline account seed for auth tests. `src/db/seeds/baseline-users.ts` is the baseline operational utility owned by T8.9 next: it adds four stable accounts with Argon2id hashes and never overwrites existing passwords/data. `db:seed` requires `DEMO_PASSWORD` with at least 12 characters; it currently seeds accounts only. Full synthetic scenarios are T8.9 work.

Contracts live in `packages/contracts/openapi.json`; run its `generate` script after an intentional contract edit, and `check` to validate types and detect generated drift without changing files. The typed `PlatformClient` seam includes all planned routes. Internal AI additions preserve the existing multipart `cv`/JSON-string `jd`, add service bearer authentication and `X-Expected-Config-Fingerprint`, `X-Request-ID`, `X-Run-ID`, and define manifest/source output for T8.3. Source page metadata follows the existing extractor (`page_number`, `text_layer|ocr`); offsets explicitly count Unicode code points. The manifest is a declared full config/build contract, not the existing display-only config. Runtime schema/hash validation is T8.3/T8.6 work.

Root `demo:reset`, `demo:backup`, `demo:restore` and `verify:t8` aliases reserve future-owned scripts and intentionally fail until T8.9/T8.11 supply them. E2E has pinned Playwright dependencies and command placeholders; scenarios and config belong to T8.11. `tests/e2e` was added to `pnpm-workspace.yaml` with coordinator approval so filtering/install/lockfile behavior works.
